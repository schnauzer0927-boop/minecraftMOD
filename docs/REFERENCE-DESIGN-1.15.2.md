# Apex 1.15.2 — HUNTER設計図への一致基準

## 使用する設計図

今回ユーザーが添付した **HUNTER / MINECRAFT MOD BOSS ENEMY / BLOCKBENCH MODEL REFERENCE** を正式な設計図とする。以前のAPEXコンセプトや1.5.1のモデルは、外観の基準にしない。正面・側面・背面・頭部詳細・前腕詳細・脚詳細・DASH POSEを同時に満たすことが目的である。

画像内の高さラベルは2.3〜2.5ブロックだが、今回の文章の指示に従い全高は約2.7ブロックへ均等に換算する。画像の体型比率は保つ。以下の数値は、添付画像を目視して得たおおよその設計範囲であり、原図の精密なピクセル計測値ではない。

全高を **H = 43.2モデル単位 = 2.7ブロック** とする。

範囲内の数値に収まるだけでは完成としない。例えば同じ外幅でも、肩・胸・腰が連続した箱になっていれば原図の輪郭に一致しない。レンダーで黒い内部フレームと独立した薄い装甲の隙間まで確認する。腰フレーム、腹部装甲、外側の股装甲は別の幅を持つ構造であり、最も外側の股装甲を胴体の幅に使わない。

**正面:** 小さい頭、細い首、幅のある薄い肩、胸のV字装甲、非常に細い腰、長い前腕刃、狭い関節、長い脚。腰の外側へ垂れる小装甲はあるが、胴体そのものを太くしない。肩の張り出しを巨大な四角いパッドに置き換えない。

**側面:** 額の先端が前へ、後頭のフィンが後ろ斜め上へ流れる。上半身の中心は腰より少し前にある。背中の3段以上のフィンは後ろ斜め下へ流れる。膝から踵を後方へ約3〜4単位折り、踵から爪を前方へ約5〜6単位戻す。足首から真下に人間の足を置かない。

**背面:** 首から腰へ細い中央背骨装甲が続き、その左右に段階的なV字装甲が重なる。背面の最外幅を肩より大きくしない。背中フィンは横へ広がる翼ではなく、厚み方向に後方へ伸びる。

## 頭・胸・前腕の識別点

頭の形だけでなく、面の色の配置を合わせる。原図の頭は、**銀〜中ガンメタルの長い額中央稜線、黒い頬と側面、低い位置の細い逆V型オレンジセンサー**を持つ。額は面積の約25〜35%を占める中明度の金属面に見える。銀を小さなエッジだけに限定した全面黒の小三角マスクは、この設計図とは異なる顔になる。

正面の顔は縦長の逆三角形で、銀色の中央額板が先端へ細くなる。センサーの上下を黒い板で覆い、発光が細い隙間に見えるようにする。鼻・口・巨大な顎は作らない。後頭には3〜4枚以上の薄い装甲フィンが重なり、角柱のトゲだけにしない。45度から中央稜線、頬、側面の別々の面が読めること。

胸は3〜5段の左右V字装甲が中央へ集まる。上面の銀〜ガンメタルと、下側の黒い隙間が区別できること。中央のオレンジは縦に細く、段の間から漏れる。幅の広い橙色の胸コアや、平らな一枚の胸板にはしない。

前腕は長い銀色の中央主刃と、両側の黒い段状補助刃で構成する。肘付近から先端へ少なくとも3段階で幅と角度が変わり、手の爪よりも下へ先端が伸びる。主刃の周囲に同寸法の長方形板を平行に置くだけでは、設計図の細長い多重刃に見えない。

## 材質・発光

暗い内部・補助装甲、中明度の主装甲、狭い明るい金属エッジを分ける。額中央、胸V、主前腕刃、太腿前板には原図と同じ中明度の金属面を残す。細い擦れは加えるが、全面に粗い汚れや迷彩を付けない。目・胸中央・背骨・刃の橙色は細く、全体の投影面積で目安1〜3%程度に見えること。最終判断は実レンダーの見た目で行う。

## 可動時の確認

首・肩・肘・手首・腰・股・膝・足首に黒い内部軸と重なり装甲を使う。静止画だけで接続して見える状態を完成としない。DASH POSEでは頭を低く、胸を前へ、フィンを後ろへ、片腕を前へ、後脚を長く伸ばす。既存のアニメーション名、時刻、攻撃発生tickは維持する。

正式モデルの[正面](visuals/apex-reference-match-front.png)、[側面](visuals/apex-reference-match-side.png)、[背面](visuals/apex-reference-match-back.png)、[頭部](visuals/apex-reference-match-head.png)は実際に表示して確認した。[12個のアニメーションサンプル](visuals/apex-reference-match-animation-poses.png)の初期出力も表示し、その時点で掲載されていたフレームで首・肩・肘・膝などが大きく分離していないことを確認した。このシートはruntime geometryとテクスチャ、アニメーション値から描いたソフトウェアレンダーであり、Minecraftの実画面ではない。

補正前のサンプルの`charge_prepare`と`charge`は、原図のDASH POSEの極端に低い前傾より直立に近かった。この差を根拠に、ユーザーが許可した必要最小限の回転補正を行うことになった。

## 前傾の最小補正の独立確認

native Blockbenchで比較した候補Bの`build/reference1152/native/candidate-B-side-225.png`と`candidate-B-45.png`を実際に表示した。補正前より胸が強く前へ倒れ、頭が下がり、後頭・背面の刃が後方へ流れる。顔のセンサーは前へ向いたまま読め、肩・首は掲載された側面と45度のフレームで大きく外れていない。原図の低い前傾へ近付ける最小補正として、この候補を承認した。

採用する補正範囲は、`charge_prepare`と`charge`の2クリップ、`chest`と`neck`の2ボーンの**rotation Xのみ・計16個の数値**である。`charge`では胸53度・首−30度、`charge_prepare`の後半では胸40度・首−20度へ補正する。腕・脚の歩行周期は変更しない。残り35クリップ、アニメーション名、フレームのキーと時刻、easing、チャンネル、position、攻撃発生tickとCombatControllerの同期は維持する。したがって、最終版を「37アニメーションの全ての値・バイトが未変更」とは説明しない。

この補正は上半身の角度だけを扱う。原図の片腕を前へ伸ばし後脚を極端に後ろへ伸ばす四肢の構図まで、完全に一致させたと主張するものではない。実機の移動・姿勢・関節・刃の貫通は`runClient`で別途確認する。

独立静止レビューと候補Bのnative画像の確認は完了した。Minecraftでの必須動作全体の確認はGUI検証担当へ引き継いでおり、その実機の結果は担当の検証記録を参照する。

## Minecraft実画面の独立静止確認

GUI検証担当が実際の`runClient`で撮影した`build/reference1152/client/plain-new-front.png`・`plain-new-side.png`・`plain-new-back.png`・`plain-new-45.png`を全て表示した。[保存したゲーム内45度画像](visuals/apex-reference-match-ingame.png)でも、細い装甲マスクとオレンジセンサー、銀色の多段Vと暗い隙間、細い腰、複合前腕刃、後方へ流れるフィン、折れ脚と爪が実際に描画されている。ソフトウェアレンダーで承認した造形から、Minecraftで別の輪郭に崩れる現象は見えない。

自然光の下で銀〜ガンメタルの主要面と黒い内部が区別できる。フィンの三角アルファ面は側面・背面・45度で黒い板として表示され、先端の白い穴やチェッカー状の抜けは見えない。首・肩・肘・膝・足首・踵は掲載された静止フレームで接続して見え、装甲が大きく浮く箇所は見えない。実ゲーム内の静止表示を承認した。

この4枚は静止撮影であり、全攻撃モーションの実行・戦闘AI・フェーズ移行の検証をこの画像だけから推定しない。それらはGUI検証担当の動作記録で別途確認する。
