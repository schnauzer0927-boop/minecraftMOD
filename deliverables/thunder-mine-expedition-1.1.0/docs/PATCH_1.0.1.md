# Thunder Mine Tools 1.0.1 — 既存ワールド用修正

更新対象は独立した補助 MOD です。**既存のワールドを保持し、補助 JAR だけを交換する方法**を優先します。Create / Sable / Simulated Coasters の添付 JAR と、コース形状・景観・保存済み車両は交換しません。

## 最初に確認する必須ファイル

**Thunder Mine Tools は任意の追加 MOD ではなく、このワールドで遊ぶために必須です。** 今回の追加情報では、旧 `thunder-mine-tools-1.0.0.jar` が未導入の可能性があります。このワールドの専用乗車ボタン・自動発車・駅停止は補助 MOD が担当するため、添付の Create / Sable / Simulated Coasters の 3 本だけではその操作が機能しません。

まず、実際に使用している起動構成の `mods` に補助 JAR があるか確認してください。未導入の場合は 1.0.1 を追加します。旧版がある場合は、旧版を外して 1.0.1 へ交換します。**1.0.0 と 1.0.1 を同時に入れないでください。**

ワールド表示名による判定不具合は、こちらの調査で別途見つけた問題です。ユーザーの症状の原因が表示名だったと確認したわけではありません。

## 修正内容

- 保存データが本アトラクションのコースと車両を示している場合、ワールドの表示名だけを理由に駅操作・走行制御を無効にしないよう修正しました。新規建設のワールド制限は別に維持します。
- 駅停止と再読込後の停止に、Sable の実際の物理拘束を使用します。
- 途中保存からの再開は、実際に保持している車両位置と元のレール拘束を確認します。車両を駅へワープして再開成功とは扱いません。
- STOP を繰り返し操作しても、明示的な停止状態と再開に必要な情報を失わないよう修正しました。
- 完走・駅停止の保存記録がある車両が旧状態で駅からずれた場合、条件を満たす車両だけを元の軌道上で低速帰還させる操作を追加しました。車両位置を直接変更せず、帰還を新たな完走成功として記録しません。
- `/mine_world status` を OP 不要の読み取り専用コマンドにしました。補助 MOD の版、ワールド表示名、コースの保存状態、車両・運転状態を表示します。

これらはコード上の変更です。**ユーザー環境で発生した「ボタンが反応しない」症状が解消したとは、まだ断定していません。** 正確な保存状態・表示された診断内容との照合が必要です。

## 既存ワールドを残して更新する

1. Minecraft を正常に終了します。ワールドを開いたまま JAR を交換しないでください。
2. 使用中のゲームディレクトリにある `saves/Coaster World - Thunder Mine Expedition` を、別の場所へフォルダごとコピーしてバックアップします。表示名・フォルダ名を変更している場合は、そのワールドをコピーします。`sublevels` と `data` も含めてください。
3. **同じ起動構成のゲームディレクトリ**にある `mods` を開きます。標準の保存先なら、Windows の `Win + R` で `%APPDATA%\.minecraft\mods` を入力できます。専用ゲームディレクトリの場合は、ランチャーの「起動構成」で使用先を確認します。
4. 旧 `thunder-mine-tools-1.0.0.jar` がある場合は、`mods` の外へ移動して保管します。`mods` 内のサブフォルダにも残さないでください。補助 MOD が未導入の場合、この手順は不要です。
5. `thunder-mine-tools-1.0.1.jar` を同じ `mods` に入れます。補助 MOD は **1 本だけ**にします。
6. 同じ Minecraft 1.21.1 / NeoForge 21.1.228 の起動構成で、既存ワールドを開きます。更新のために既存ワールドへ ZIP を上書きしたり、建設コマンドを実行したりする必要はありません。

必要な構成は次の 4 本です。

```text
create-1.21.1-6.0.10.jar
sable-neoforge-1.21.1-2.0.6.jar
simulatedcoasters-0.1.5.jar
thunder-mine-tools-1.0.1.jar
```

Java は 21 を使用します。第三者 MOD は今回の添付ファイル、または [MOD 一覧](MOD_LIST.md) に記載した同一の公開版を使用してください。Flywheel / Ponder / Veil 等の同梱依存を別途追加する必要はありません。

新規導入用には、`mods` 内の補助 JAR、`saves` 内のワールド、README をまとめた軽量な導入セットを配布する予定です。第三者 MOD の 3 本は同梱せず、同じゲームディレクトリへ導入済みのファイルを利用します。既存ワールドを更新する場合は、導入セットでワールドを上書きせず、補助 JAR だけを取り出してください。導入セットの公開とダウンロード先は、最終検証後に案内します。

## 駅の操作

| 操作 | 動作 |
|---|---|
| 木製 BOARD ボタンを右クリック | 停止中の車両の Create 座席へ乗車。初回は約 3 秒待って自動発車 |
| 灰色の石製 START ボタン | 駅に停止している車両を手動発車。条件を満たす旧車両が駅からずれた場合は、低速の駅帰還を開始 |
| 黒い石製 EMERGENCY STOP ボタン | 安全停止。明示的な緊急停止を自動発車で解除しない |
| 駅へ帰還して停止中に `Shift` | 降車 |
| 降車せず乗り続ける | 帰還後の駅待機約 10 秒後に再発車 |

通常の乗車に OP・チート・コマンドは不要です。手動で緊急停止した車両を途中から再開する管理操作には OP 相当の権限が必要です。途中退出や再読込で車両を駅へ自動移動しません。

専用 BGM は追加していません。警告音などは Minecraft の音量設定に従います。音声の聞こえ方と Windows 実機の性能は未検証です。

## 駅からずれた旧車両を戻す場合

1.0.1 には、保存済みの完走・駅停止記録がある車両に限定した帰還操作があります。駅の灰色の START ボタン、または管理者の次のコマンドで開始します。

```text
/mine_world return_to_station
```

管理者コマンドには OP 相当の権限が必要です。駅の灰色ボタンは通常のプレイヤーも操作できます。元の車両を既存のレールに拘束したまま、最大 3.2 ブロック/秒の低速で次の駅まで走らせます。駅へ瞬間移動したり、その帰還だけで 1 周完走と記録したりしません。

車両 UUID、コースの指紋、元のレール接続、保持状態、保存済み完走記録が一致しない場合や、破損・未完走の車両には帰還を許可しません。拒否された場合はデータを作り直さず、診断内容を記録してください。この帰還操作の実機検証結果は、上の表へ別途追記します。

## 反応しない場合の診断

チャットで次を実行します。OP やチートを有効化しなくても使用でき、コースを編集・再建設せずに状態を確認するコマンドです。

```text
/mine_world status
```

表示に `Thunder Mine Tools 1.0.1` があるか確認してください。旧版の表示や「不明なコマンド」の場合は、起動構成のゲームディレクトリと `mods` の補助 JAR を確認します。

コース・車両が未読込、保存状態不一致、停止状態の場合は、その診断内容を記録してください。保存データの不一致を解消しようとして既存ワールドへ `/mine_world build` を実行しないでください。更新後も症状が続く場合は、表示されたステータスと `logs/latest.log` の該当エラーが原因の切り分けに役立ちます。
